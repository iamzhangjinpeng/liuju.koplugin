# 留句：开发流程

设计日期：2026-11-03  
产品依据：[产品意图](PRODUCT-INTENT.md)

## 开发顺序

先用实际尺寸的样图确定视觉，再完成标注到图片的生成链路，最后接入随机屏保、换书切换与异常恢复。每个阶段都有独立产物和进入下一阶段的条件。

```mermaid
flowchart LR
    A[确认设备与接口] --> B[确定壁纸视觉稿]
    B --> C[完成一条标注到 PNG]
    C --> D[同步当前书图片池]
    D --> E[接入随机屏保]
    E --> F[实机验收与发布]
```

## 阶段 0：确认设备、接口与数据规则

**产物：一份接口核验记录和少量匿名化的标注样本。**

1. 记录实际使用的 Kindle 型号、屏幕分辨率与 KOReader 版本，作为首版明确的支持目标。
2. 核对当前文档、书名、封面和已保存标注的读取方式。以 EPUB 为主验证核心流程，PDF 排除在首版范围外。
3. 核对创建日期、修改日期、原文与笔记字段，以及标注新增、编辑、删除后的事件。
4. 核对打开书籍、切换文档、关闭阅读界面和插件停用的生命周期。
5. 核对目标版本的睡眠屏保设置项、随机图片目录、目录文件数量限制与 PNG 渲染方式，确认大量合格标注也能进入随机选择范围。

已从公开源码确认的参考点：

- `readerannotation.lua` 中的 `datetime` 表示标注创建时间，`datetime_updated` 表示后续修改时间。
- `readerhighlight.lua` 会发送 `AnnotationsModified` 事件。接入时仍需核验删除、导入等其他标注变化是否覆盖完整。
- `screensaver.lua` 的随机图片模式会从选定目录取图。留句可以专注生成和维护目录。
- 单向历插件提供了屏保设置备份、应用和恢复的可参考实现。

**通过条件：**能从当前打开的书中取得一条高亮、一条带笔记的标注和封面；确认实际可用的日期与变更事件；生成一张设备可显示的 PNG。

## 阶段 1：先选定好看的壁纸

**产物：少量原生屏幕尺寸样图、一套选定版式和视觉参数表。**

先使用固定样本出图，比较封面放置、正文区域、日期落款与留白。候选样式控制在 2—3 个，最终首版保留一套主要版式。

样本至少覆盖：

| 样本 | 观察重点 |
| --- | --- |
| 约 15 字的短摘录 | 画面是否完整，短文字能否自然停留 |
| 约 50 字的摘录 | 正文、封面与留白是否平衡 |
| 80 字的边界内容 | 固定字号下是否仍然从容、完整 |
| 原文加笔记，合计不超过 80 字 | 两种文字层次是否清楚 |
| 长书名、深色封面、浅色封面、缺失封面 | 版式与灰阶是否稳定 |
| 显式换行、中文与英文混排 | 换行与实际占用空间是否正常 |

在实际 Kindle 上观察字号、线条、灰阶和正常阅读距离下的可读性。电脑预览用于发现排版问题，实机决定最终效果。

参数表固定正文的字号、行距、正文区域、最小留白、封面比例、书名区高度和日期样式。字数达标但空间不足的条目必须被识别并跳过。

**通过条件：**选定样式在短、中、上限三种长度下都达到同一审美标准；完成图与实际锁屏显示一致。

## 阶段 2：跑通一条标注到一张图片

**产物：手动触发即可生成的第一条完整链路。**

将流程划分为四个职责明确的部分：

| 部分 | 输入与输出 |
| --- | --- |
| 内容读取 | 当前文档与标注 → 书籍信息、原文、笔记、创建日期 |
| 资格判断 | 内容与上限 → 可生成，或明确的跳过原因 |
| 固定版式渲染 | 合格内容与屏幕尺寸 → 完整壁纸画面 |
| 图片保存 | 完成画面 → 有效 PNG 与对应记录 |

关键规则：

- 采用 UTF-8 / Unicode 字符计数，避免把中文的字节数当字数。
- 带有笔记时，原文与笔记合并计数；空内容跳过。
- 使用实际排版高度进行第二道筛选，正文完整显示才出图。
- 日期来自原始标注，正文保持原文和笔记。
- 输出分辨率匹配设备；封面在内部按比例缩放。
- PNG 先写临时文件，成功后再替换正式文件；随机目录只接收有效成图。

**通过条件：**手动选择一条合格标注能得到预期 PNG；边界和超限内容的结果符合产品规则；书籍文件与标注数据保持完整。

## 阶段 3：同步当前书的图片池

**产物：按书隔离、可增量更新的本地图片目录。**

建议目录：

```text
/mnt/us/koreader/screenshots/liuju/
└── <book-id>/
    ├── <annotation-key>-<content-hash>.png
    └── ...
```

索引和临时文件放在插件自己的数据位置，与可供屏保选择的 PNG 分开。书籍标识、标注标识及内容摘要的具体生成方式，在阶段 0 的数据核验后确定；位置等信息可以用于内部识别，壁纸上仍省去页码和章节。

同步行为：

1. 打开书籍后，只读取当前书的标注，生成缺失或已变化的图片。
2. 新增标注后补图；编辑后更新；删除后移除对应成图。
3. 修改字数上限、版式或设备尺寸后，重新核对当前书的合格图片。
4. 切换书籍时取消旧文档尚未完成的任务，随后切换图片池。
5. 旧书目录保留作缓存，重开时复用有效成图。

任务每次处理少量条目，让阅读界面能够继续响应。每项任务绑定书籍身份，落盘或切换屏保前再次确认目标，防止旧书任务覆盖新书状态。

通过索引确认生成文件的归属，仅更新、移除留句自身管理的文件。重复执行同步应得到相同结果。

**通过条件：**新增、编辑、删除、调低上限和换书后，当前图片池都与数据一致；重复打开同一本书不会增生重复图片。

## 阶段 4：接入随机睡眠屏保

**产物：启用后自动生效、停用后可恢复的屏保集成。**

插件首次启用默认开启留句屏保。实际接管时先备份相关设置，再将 KOReader 的屏保指向当前书的图片目录，采用随机图片模式，并关闭额外的睡眠提示文字。当前书尚无合格图片时显示该书的静态封面壁纸；没有封面则生成统一书名封面。回退图片单独保存，避免核心屏保的回退逻辑误取上一本文字。第一张有效小票保存成功后，再切换为该书的随机图片目录。

接入时同时核对按文件名轮播开关、休眠专属选项等覆盖设置，确保实际显示符合随机选择规则。实际改变的设置项均纳入备份与恢复。

真正进入休眠时直接显示已有图片。批量渲染安排在阅读期间；退出 KOReader 后的系统锁屏由设备原有机制管理。

单向历与留句都会修改同一套屏保选项，需要安排下面的集成规则：

- 用户选择留句作为当前屏保后，由留句管理该配置；单向历的自动配置需要关闭。
- 留句读取实际配置判断自己是否仍在管理屏保；用户或其他插件改变配置后，留句不应在后台反复抢回。
- 恢复设置前确认当前配置仍属于留句，避免覆盖用户之后作出的屏保选择。
- 停用、删除插件与阅读界面正常切换分别处理，避免每次关书就错误恢复屏保。

首版设置菜单按照产品文档保持精简。开发诊断信息可以记录到日志中，用于定位跳过原因、目录切换和任务取消。

**通过条件：**当前书休眠能显示自己的图片；换书后不会显示上一本文字；空图片池有稳定回退；停用后恢复行为正确；与单向历切换时不会反复争用配置。

## 阶段 5：验收、打包与首次发布

**产物：验收记录、实际 Kindle 锁屏照片、可直接安装的发布包。**

自动检查集中在容易产生真实缺陷的边界：

- 79、80、81 字，中文、标点、空白和中英混排的资格判断。
- 空标注、原文加笔记、缺失日期、缺失封面及大量换行。
- 标注增删改、上限改变、换书后旧任务返回与文件更新中断。
- 重复同步的幂等性、文件归属，以及屏保配置备份和有条件恢复。

实机验收覆盖：

| 验收项 | 预期结果 |
| --- | --- |
| 短、中、上限长度 | 文字完整且留白协调，字号稳定 |
| 超限或排不下 | 条目跳过，图片池中没有挤压或截断的成图 |
| 封面与日期 | 封面比例正确，日期来源和展示正确 |
| 同一本书多次打开 | 已有效的图片得到复用 |
| 切换两本书并多次休眠唤醒 | 每次均来自当前书的图片池 |
| 当前书没有可用小票 | 显示当前书封面，或按无封面约定回退 |
| 启用、停用与切换单向历 | 屏保选择与恢复符合用户操作 |
| 文件管理器、重启与插件停用 | 目录选择稳定，待执行任务正确结束 |

实际测试的 Kindle 型号与 KOReader 版本需要写进发布说明。其他设备按待验证范围标注。

发布包命名为 `liuju.koplugin-v0.1.0.zip`，解压后直接得到：

```text
liuju.koplugin/
├── _meta.lua
├── main.lua
├── ...运行模块
└── README.md
```

发布说明包含安装路径、字数规则、图片保存位置、屏保回退与恢复方式，以及选定版式的真实成图。首版通过内容一致性和实机视觉两项验收后再发布。
